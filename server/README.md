# Сервер мероприятий ПГУ

Отдельный бэкенд для приложения «Мероприятия». Хранит общий список в базе SQLite, отдаёт его телефонам по HTTP и даёт веб-админку, где можно смотреть все записи, добавлять и удалять их.

Добавление и удаление в самом приложении (у администратора) тоже пишут в эту же базу. Панель «ввести IP» в приложении нет: адрес сервера зашит в конфиг приложения.

---

## Что это даёт

| Без сервера | С сервером |
| --- | --- |
| У каждого телефона свой локальный кэш | Один общий список для всех |
| Правки видны только на одном устройстве | Правки из админки и из приложения доходят до всех при обновлении списка |

Пока сервер не запущен или недоступен, приложение показывает мероприятия, сохранённые на телефоне с прошлой успешной синхронизации.

---

## Что нужно установить

### Для запуска на своём компьютере (тест)

1. **Dart SDK** (уже есть, если установлен Flutter).
   Проверка:

   ```powershell
   dart --version
   ```

2. Папка проекта `server` из этого репозитория (`D:\FlutterProjects\my_app\server`).
3. Открытый порт **8080** в брандмауэре Windows (при запросе разрешите доступ в частной сети).
4. Для телефона по USB — **ADB** (идёт с Android SDK / Flutter).

### Для работы из интернета / Play Market

1. Всё то же, плюс **VPS** (виртуальный сервер) с Ubuntu или похожей ОС.
2. Желательно **домен** (не обязательно, но удобно для HTTPS).
3. **Nginx** (или другой reverse proxy) и сертификат **Let’s Encrypt** для HTTPS.
4. В приложении прописать этот публичный адрес в `serverUrl` и пересобрать APK/AAB.

Без VPS в интернете телефоны из Play Market к вашей базе не подключатся: домашний ноутбук из магазина «не виден».

## Структура папки `server`

```
server/
  bin/server.dart      — точка входа, запуск HTTP
  lib/
    config.dart        — порт, токен, логин/пароль админки
    database.dart      — SQLite
    api.dart           — REST API
    event.dart         — модель мероприятия
    seed.dart          — начальные учебные записи
    university.dart    — справочник филиалов для формы
  web/admin.html       — веб-админка
  data/events.db       — база (создаётся при первом запуске, в git не попадает)
  pubspec.yaml
  README.md            — этот файл
```

## Настройки перед запуском

Файл сервера: `server/lib/config.dart`

| Параметр | Смысл | Значение по умолчанию |
| --- | --- | --- |
| `port` | Порт HTTP | `8080` |
| `adminToken` | Секрет для POST/DELETE из приложения и админки | `pgu-a8f3c9e2b7d14e6f90a2c5d8b1e4f7a3` |
| `adminUser` | Логин веб-админки | `admin` |
| `adminPassword` | Пароль веб-админки | `pgu-Admin-Panel-7f3a` |
| `databaseFileName` | Имя файла SQLite | `events.db` |

Файл приложения: `../lib/config/app_config.dart`

| Параметр | Смысл |
| --- | --- |
| `serverUrl` | Адрес, куда ходит приложение |
| `adminToken` | **Должен совпадать** с `ServerConfig.adminToken` |
| `adminAccessCode` | Код «Войти как администратор» в профиле приложения (`pgu-admin`) |

Перед выкладкой в интернет обязательно смените `adminToken`, `adminUser` и `adminPassword`. Тот же новый `adminToken` пропишите в приложении и пересоберите его.

## Запуск на своём компьютере

Откройте **отдельное** окно терминала. Пока телефоны должны видеть общий список, это окно **не закрывайте**.

```powershell
cd D:\FlutterProjects\my_app\server
dart pub get
dart run bin/server.dart
```

В консоли появятся примерно такие строки:

```
Сервер мероприятий ПГУ запущен
База SQLite: ...\server\data\events.db
Админка: http://127.0.0.1:8080/admin
API:     http://127.0.0.1:8080/events
Эмулятор Android: http://10.0.2.2:8080
Телефон в этой сети: http://192.168.x.x:8080
```

### Проверка

1. В браузере откройте `http://127.0.0.1:8080/events` — должен прийти JSON со списком.
2. Откройте `http://127.0.0.1:8080/admin` — браузер спросит логин и пароль (`admin` / пароль из `config.dart`).
3. В админке в поле токена должен быть тот же `adminToken`, что в конфиге (по умолчанию уже подставлен).

### База данных

- Файл: `server/data/events.db`
- При **первом** запуске создаётся таблица `events` и заливаются учебные мероприятия из `lib/seed.dart`
- Дальше все добавления и удаления идут только в эту базу
- Чтобы начать с нуля: остановите сервер, удалите `data/events.db`, запустите снова

## Как подключить телефон / эмулятор

Адрес задаётся **только** в приложении:

`lib/config/app_config.dart` → `serverUrl`

После смены адреса перезапустите приложение (горячей перезагрузки мало: лучше полный `flutter run` или переустановка).

### Вариант A. Телефон по USB (без общей Wi‑Fi)

1. В `app_config.dart`:

   ```dart
   static const serverUrl = 'http://127.0.0.1:8080';
   ```

2. Запустите сервер на компьютере.
3. В другом окне:

   ```powershell
   adb reverse tcp:8080 tcp:8080
   ```

4. Запустите приложение на телефоне.

### Вариант B. Эмулятор Android на этом же ПК

```dart
static const serverUrl = 'http://10.0.2.2:8080';
```

`10.0.2.2` — это «localhost компьютера» глазами эмулятора.

### Вариант C. Телефон в той же Wi‑Fi, что и ноутбук

1. В выводе сервера найдите строку `Телефон в этой сети: http://192.168....:8080`
2. Пропишите этот адрес в `serverUrl`
3. Телефон и компьютер в одной сети, гостевой Wi‑Fi иногда режет доступ между устройствами

### Вариант D. Интернет / Play Market

```dart
static const serverUrl = 'https://ваш-домен.ru';
```

Сервер должен быть на VPS (см. ниже), с HTTPS.

Список в приложении обновляется при открытии и при потягивании главной вниз. При возврате в приложение из фона тоже идёт обновление.

## Веб-админка

Адрес: `http://127.0.0.1:8080/admin` (или ваш домен + `/admin`).

1. Браузер запросит **логин и пароль** (Basic Auth из `config.dart`).
2. На странице введите **токен** (`adminToken`) и нажмите «Сохранить» — он запомнится в браузере.
3. Слева — все мероприятия из базы, справа — форма добавления.
4. «Удалить» сразу убирает запись из SQLite.

То же можно делать в приложении: профиль → «Войти как администратор» → код `pgu-admin` → кнопки «Добавить» / «Удалить мероприятие».

## Как поднять сервер в интернете (VPS)

Ниже — типовой путь на Ubuntu. Имена провайдера и домена подставьте свои.

### 1. Арендуйте VPS

Любой простой тариф с Ubuntu 22.04+, публичным IP и доступом по SSH.

### 2. Установите Dart на сервере

По [официальной инструкции Dart](https://dart.dev/get-dart) для Linux, либо через готовый пакет вашего дистрибутива. Проверка: `dart --version`.

### 3. Скопируйте папку `server` на VPS

Например через `scp`, `rsync` или git clone всего репозитория. На сервере работайте из каталога `server`.

### 4. Смените секреты

В `lib/config.dart` на VPS задайте новые `adminToken`, `adminUser`, `adminPassword`.  
В приложении в `adminToken` поставьте **тот же** токен. В `serverUrl` — ваш HTTPS-адрес.

### 5. Первый запуск вручную

```bash
cd /path/to/server
dart pub get
dart run bin/server.dart
```

Убедитесь, что `http://IP:8080/events` открывается (пока без HTTPS). Остановите процесс (Ctrl+C).

### 6. Автозапуск через systemd (чтобы не падал после выхода из SSH)

Создайте файл `/etc/systemd/system/pgu-events.service`:

```ini
[Unit]
Description=PGU events server
After=network.target

[Service]
Type=simple
WorkingDirectory=/path/to/server
ExecStart=/usr/bin/dart run bin/server.dart
Restart=always
RestartSec=3
User=ubuntu

[Install]
WantedBy=multi-user.target
```

Подставьте свой путь к `dart` (`which dart`) и пользователя. Затем:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now pgu-events
sudo systemctl status pgu-events
```

### 7. Nginx + HTTPS

Установите Nginx и certbot, создайте сайт с проксированием:

```nginx
server {
    listen 80;
    server_name ваш-домен.ru;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Выпустите сертификат:

```bash
sudo certbot --nginx -d ваш-домен.ru
```

В приложении:

```dart
static const serverUrl = 'https://ваш-домен.ru';
```

Пересоберите и опубликуйте приложение.

### 8. Фаервол

На VPS откройте 80 и 443. Порт 8080 лучше **не** открывать наружу — к нему ходит только Nginx на localhost.

## API (для приложения и отладки)

Базовый URL — ваш `serverUrl` без слэша в конце.

| Метод | Путь | Заголовок | Назначение |
| --- | --- | --- | --- |
| GET | `/events` | — | Все мероприятия (JSON-массив) |
| POST | `/events` | `X-Admin-Token` + JSON тело | Добавить |
| DELETE | `/events/{id}` | `X-Admin-Token` | Удалить |
| GET | `/meta/university` | — | Справочник филиалов/типов для админки |
| GET | `/health` | — | Проверка, что процесс жив |
| GET | `/admin` | Basic Auth | HTML-админка |

Пример добавления (PowerShell):

```powershell
$body = @{
  id = "manual_1"
  title = "Тест"
  description = "Описание"
  start = "2026-11-01T10:00:00"
  end = "2026-11-01T12:00:00"
  location = "Ауд. 1"
  type = "seminar"
  directionId = "ryb-tech-cs"
  course = 2
  branchId = "ryb"
} | ConvertTo-Json

Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/events `
  -ContentType "application/json; charset=utf-8" `
  -Headers @{ "X-Admin-Token" = "pgu-a8f3c9e2b7d14e6f90a2c5d8b1e4f7a3" } `
  -Body $body
```

Типы мероприятий: `conference`, `olympiad`, `seminar`, `workshop`, `cultural`.

## Безопасность (кратко)

- Читать список может тот, кто знает URL — для афиши мероприятий это обычно нормально.
- Менять данные без токена нельзя.
- Админка без логина/пароля не открывается.
- В продакшене обязательны **HTTPS**, свои длинные секреты и закрытый снаружи порт 8080.
- Не коммитьте боевые пароли в публичный git, если репозиторий открытый.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| В приложении «Нет связи с сервером» | Сервер запущен? Верный `serverUrl`? Для USB сделан `adb reverse`? |
| Админка просит пароль снова и снова | Логин/пароль из `server/lib/config.dart`, не код `pgu-admin` из приложения |
| Добавление из админки «отклонено» | Неверный или старый токен в поле на странице |
| Телефон в Wi‑Fi не видит сервер | IP из вывода сервера, одна сеть, брандмауэр Windows разрешил Dart/порт 8080 |
| После публикации в Play Market список пустой/старый | В сборке всё ещё `127.0.0.1` — нужен публичный `https://…` и пересборка |
| База «пропала» после копирования проекта | Файл `data/events.db` локальный; на новом месте создастся заново с сидом |
